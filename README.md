# Along · AI Fashion Studio

面向不熟悉提示词的服装商家：选择人物、动作和场景，组合成可以复制的中英文商品图提示词。目前主工作台聚焦男装与女装长裤。

线上地址：https://8yfish.github.io/along/

## 使用方式

1. 打开首页，选择男装或女装，默认进入“快速搭配”。
2. 选择“我有商品参考图”或“我想凭描述生成”。参考图模式需要在出图工具中同时提供商品图；本页不上传图片、不调用出图 API。
3. 使用“清晰展示版型 / 日常穿搭感 / 轻松休闲感”开始，或自行选择人物、动作、场景。
4. 在详细设置中调整年龄、体型、构图、情绪和补充要求。存在动作与构图冲突时，按提示修正后再复制。
5. 复制中文或英文提示词，到所使用的出图工具生成图片，并核对商品细节。

英文商品描述与英文补充说明均可选。未填写英文版本时，英文稿保留中文原文，不会自动翻译。

## 方案与一致性

- 人物库、场景库、主工作台的选择会同步。
- 当前选择自动保存在浏览器的 `localStorage` 中；男女装各自独立。
- 可命名保存最多 12 套方案，并载入或删除。
- “锁定”用于在换一组搭配时保持选中的参数。它不能保证出图工具生成完全相同的人脸；需要人物一致性时，应使用该工具的人物参考功能。
- 保存仅在当前浏览器和网站地址下生效，清除浏览器数据会移除方案。不具备账号同步功能。

## 本地运行

这是一个静态网站，不需要安装 npm 依赖或配置 API Key。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

浏览器打开 `http://127.0.0.1:8765/`。建议通过 HTTP 服务访问，以便正常使用剪贴板与本地保存。

## 验证

使用 Node.js 22 或更新版本：

```powershell
node --test tests/prompt-engine.test.cjs
```

测试覆盖提示词性别、动作与构图约束、参考图与文生图模式、中文补充保留、跨页面状态同步、方案恢复，以及男女装真实图库的姿势 / 场景 / 构图组合。另检查脚本语法和图库资源路径。

## 文件结构

- `index.html`：男装 / 女装入口。
- `generated-images.html`、`generated-images-women.html`：现有图库和详细参数界面。
- `assets/studio.js`：共用的快速搭配、跨页同步、浏览器保存与冲突提示。
- `assets/prompt-engine.js`：男女装共用的提示词规则，不依赖网络。
- `assets/studio.css`：桌面与手机布局。
- `assets/gallery/`：从原页面内嵌数据中提取的图片，按内容哈希命名，重复图片共用文件并按需加载。
- `tests/prompt-engine.test.cjs`：自动化回归测试。

GitHub Pages 可直接发布仓库根目录，无构建步骤。其余历史 HTML 页面保留原有入口。

背面展示：在快速搭配的动作卡中点击“背面展示”，即可切换为背面全身图；也可在详细设置中改为下半身。背面使用真人动作参考照片，不代表所选人物或商品款式。参考图模式应在出图工具中补充商品背面图，以保留后口袋、后腰与图案细节。

## 视频提示词工作台

在“快速搭配”切换到“视频提示词”，即可基于当前人物、动作、场景和构图生成一段连续镜头的视频脚本。

- 图生视频 / 文生视频两种输入。图生视频推荐先在出图工具中生成并确认完整的人物商品主图，再用该图作为首帧。
- 目标时长为 5 / 8 / 10 秒，画幅为 9:16 / 16:9 / 1:1；这些是创作目标，不代表任意模型都支持，实际参数需在所用工具中选择。
- 人物动态支持轻微呼吸、缓慢行走、小幅转身、面料轻动；镜头支持固定、缓慢推进、平稳跟随。
- 自动生成“开场 / 动作 / 收尾”三个连续阶段的时间轴，并保持人物、服装和背景的连续性。
- 背面视频全程保持背对镜头，不做 360° 转身。坐姿 / 蹲姿与站立转身、行走冲突时，先提示修正。
- 可在本地选择 JPG、PNG 或 WebP 首帧参考图（不超过 10 MB）预览；图片不上传、不写入方案、不写入浏览器存储。刷新或切换男女装后需重新选择。
- 视频参数随草稿和命名方案保存。支持复制中英文，以及导出中英文 TXT。

当前功能只生成视频提示词和脚本，不调用视频模型、不消耗生成额度，也不直接产出 MP4。

`assets/video-engine.js` 为不依赖网络的共用视频脚本规则。真人背面照片的来源与许可入口见 `assets/views/README.md`。

## 建议的后续迭代顺序

1. **商品档案**：同一商品关联正面、背面、细节图，分别设置“保留人物 / 更换人物 / 只换背景”。避免将图库动作图误当商品图。
2. **真人动作图库**：按动作、展示方向、构图给每张照片补充元数据，逐张审核图文是否一致；记录来源和使用范围。
3. **先确认主图再做视频**：在人物身份、颜色、口袋、图案和版型通过检查后，把该主图作为图生视频首帧。先做单镜头轻微动态，再增加多镜头。
4. **真正的视频生成后端**：保留 GitHub Pages 前端，通过单独部署的后端保存 API 凭据、校验参数、提交任务并返回任务 ID。前端轮询进度，成功后预览与下载；失败时保留输入并可重试。
5. **模型适配与费用提示**：选定视频供应商后，再用官方参数范围约束时长、画幅、首尾帧与并发；提交前展示预计费用。不要把模型密钥写入静态前端。
